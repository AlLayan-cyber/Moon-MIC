# Physical Capsule Engine — этап 5: ядро на C++ в тестовом стенде

Дата: 2026-11-22 · Код: `research/capsule_engine_cpp/` (отдельный стенд, без JUCE и без плагина)

## Сборка и запуск
```
.venv/Scripts/python.exe -m research.capsule_engine.export_reference research/capsule_engine_cpp/build/reference
cmake -S research/capsule_engine_cpp -B research/capsule_engine_cpp/build -G "Visual Studio 18 2026"
cmake --build research/capsule_engine_cpp/build --config Release
research/capsule_engine_cpp/build/Release/CapsuleBench.exe research/capsule_engine_cpp/build/reference
```

## Что в ядре (`CapsuleEngine.h`)
- `KorenTriode`: закон лампы и аналитические частные производные. Константы 6AU6A — из подбора этапа 2.
- `CommonCathodeStage`: каскад C-800G (плата MA-55), трапециевидные компаньоны. Ньютон в вилке, старт с решения предыдущего сэмпла, не более 40 итераций. Без выделения памяти и блокировок.
- `ConstantChargeCapsule`: капсюль с постоянным зарядом, квадратура по 64 кольцам.

## Результаты (21/21)
- **C++ против Python:** 6 сигналов каскада (малый и большой синус, импульс, мультитон, перегрузка 500 В, 96 кГц с другой нагрузкой и смещением) и 2 случая капсюля. Расхождение ≤ 4·10⁻¹⁵ относительно пика, то есть на уровне округления double. Рабочие точки совпадают точно.
- **Смена частоты дискретизации** (44,1 / 48 / 88,2 / 96 / 192 кГц): выход конечен, усиление на 1 кГц одинаково до 5 знаков.
- **Итерации на сэмпл:** 3–4 на обычных сигналах, до 7 при перегрузке. Худший случай ограничен 40.
- **Процессор** (Release, MSVC, один экземпляр, double):
  - 48 кГц: ~500 нс/сэмпл, 2,4 % ядра;
  - 192 кГц (= передискретизация 4× от 48 кГц): ~510 нс/сэмпл, 9,8 % ядра.

## Найденные и исправленные ошибки решателя
1. Численная производная (шаг 10⁻⁹·Ip) шумела, и Ньютон упирался в 40 итераций на каждом сэмпле. Заменена аналитической.
2. Проверка сходимости стояла после защиты вилки. Если корень попадал точно на край вилки, шаг отбрасывался, и решатель уходил в бисекцию. Порядок исправлен в Python и в C++.
- Python-проверки этапа 2 после исправлений: 21/21.

## Что дальше
- **Производительность.** 9,8 % ядра на экземпляр при 4× — много для плагина. Резервы:
  - не вычислять концы вилки, когда старт с прошлого сэмпла сходится;
  - вычисления во float там, где точность позволяет (проверить по эталону);
  - таблица Ip(Ugk, Upk) с интерполяцией вместо pow/log/exp;
  - 2× вместо 4× (по этапу 2 алиасинг уже при 2× упирается в пол измерения).
- **Сеточный ток** для перегрузок (сейчас сетка при 500 В на входе не ограничивается).
- **Встраивание в плагин:** только после согласования и по команде заказчика.
