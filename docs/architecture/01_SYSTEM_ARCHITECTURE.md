# 01 — Системная архитектура

Дата: 2026-11-21 · Статус: проект. Интерфейсы описаны концептуально, без кода.

## 1. Концепция Hybrid DSP + AI Analysis

```
                   ┌─────────────────────────────────────────────┐
                   │      Analysis thread (control rate)          │
 audio in ──┬─────►│  AI Analysis Engine ──► Adaptive Control     │
            │      │   (только TRANSFORM)      Engine              │
            │      └───────────────────────────┬─────────────────┘
            │                                  │ сглаженные параметры
            │                                  ▼ (lock-free, без блокировок)
            │      ┌─────────────────────────────────────────────┐
            └─────►│      Audio thread (audio rate)               │
                   │  Transformation Engine (TRANSFORM)           │
                   │        └► Microphone Modeling Engine ──► out │
                   │  SIGNATURE: только Microphone Modeling Engine│
                   └─────────────────────────────────────────────┘
```

| Движок | Ответственность | Поток | Режимы |
|---|---|---|---|
| **DSP Engine** (каркас) | Обработка звука в реальном времени: стабильность, низкая задержка, предсказуемость. Включает Modeling и Transformation | audio | оба |
| **Microphone Modeling Engine** | Измеренные свойства микрофона: частотные, фазовые, пространственные (включая proximity), нелинейные, шум (см. 02–04) | audio | оба |
| **Transformation Engine** | Компенсация исходного микрофона и позиции, применение целевой модели (см. 05) | audio | TRANSFORM |
| **AI Analysis Engine** | Анализ вокала: сибилянты, согласные, гласные, форманты, атаки, динамика, спектр; оценка исходного микрофона и позиции (см. 06) | analysis | TRANSFORM |
| **Adaptive Control Engine** | Перевод результатов анализа в параметры DSP со сглаживанием и ограничениями (см. 06) | analysis → audio | TRANSFORM |

## 2. Поток сигнала

**SIGNATURE (детерминированный):**
```
вход (считается эталонным «акустическим» сигналом)
 → калибровка уровня dBFS → SPL
 → пространственная модель H(f, θ, φ, r) [дистанция, угол, направленность; proximity]
 → нелинейная модель капсюля и электроники микрофона (оверсэмплинг)
 → собственный шум (опция, по умолчанию выключен)
 → выход
```
Дистанцию, угол и направленность задаёт пользователь. Ничего не меняется автоматически.

**TRANSFORM:**
```
вход (запись с исходного микрофона)
 → калибровка уровня
 → регуляризованная инверсия модели исходного микрофона с позиции (r_s, θ_s)
 → целевая пространственная модель в позиции (r_t, θ_t)
 → целевая нелинейность → выход
Параметры r_s, θ_s, уровень и тип исходного микрофона приходят от Adaptive Control (или от пользователя).
```

## 3. Частоты и потоки
- **Audio rate:** непрерывная обработка без выделения памяти и блокировок в аудиопотоке.
- **Control rate:** AI-анализ кадрами 10–20 мс (INFERRED, уточняется в 06) в отдельном потоке. AI не обрабатывает каждый сэмпл.
- **Передача параметров:** через lock-free очередь или атомарные структуры. В аудиопотоке параметры сглаживаются, чтобы не было «ступенек».
- **Pre-analysis (опция):** анализ всего дубля заранее (например, через ARA2 там, где DAW его поддерживает). Тот же Adaptive Control, но с полным контекстом.

## 4. Концептуальные интерфейсы (не код)
- `MicModel` — набор данных одной модели: пространственное ядро, нелинейный блок, шум, метаданные (экземпляр, дата измерения, источник, теги).
- `PositionState` — {r, θ, φ}, задаётся пользователем (SIGNATURE) или Adaptive Control (TRANSFORM).
- `LevelCalibration` — соответствие dBFS → dB SPL.
- `ControlFrame` — набор параметров на кадр управления с меткой времени и доверием (confidence).
- `ModelDataManifest` — версия данных, хэши, ссылка на конвейер обработки (`data/manifests/`).

## 5. Задержка
- **Режим с низкой задержкой:** минимально-фазовые фильтры. Задержка складывается из оверсэмплинга нелинейности и буфера анализа. AI-анализ в real-time причинный и не добавляет lookahead.
- **Режим высокой точности:** сохранение измеренной excess phase и линейно-фазовые компоненты (см. 04). Задержка корректно сообщается хосту.
- Цифры задержки — UNKNOWN до прототипа.

## 6. Журнал решений

| ID | Дата | Решение | Обоснование |
|---|---|---|---|
| D-001 | Принято с начала проекта, записано 2026-11-21 | **SIGNATURE без AI**, полностью детерминирован | Реальный микрофон не «знает», что звучит сибилянт: его передаточная функция одна для любого сигнала. Адаптация по типу звука сделала бы модель недостоверной |
| D-002 | 2026-11-21 | **Hybrid DSP + AI Analysis.** AI анализирует и управляет, но не генерирует и не переписывает звук | Сохранение артикуляции и предсказуемость |
| D-003 | 2026-11-21 | **Proximity effect в обоих режимах**, индивидуальная кривая на каждый микрофон, направленность, угол и частоту | Эффект определяется градиентной составляющей конкретного капсюля. Одна кривая на всех — недостоверно |
| D-004 | 2026-11-21 | **Предусилители — отдельный этап** после микрофонного ядра | Документации и измерений для 1073 и MP1A недостаточно (см. `docs/research/`) |
| D-005 | 2026-11-21 | **«Нет данных — нет модели»** | Профессиональная достоверность важнее количества моделей |
