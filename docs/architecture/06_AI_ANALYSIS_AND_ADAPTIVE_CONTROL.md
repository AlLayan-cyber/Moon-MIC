# 06 — AI Analysis Engine и Adaptive Control Engine

Дата: 2026-11-21 · Статус: исследование · Применяется **только в TRANSFORM** (решение D-001)

## 1. Принцип
AI — анализатор и контроллер, а не генератор. Он не создаёт и не переписывает вокальный сигнал. Приоритет — сохранение артикуляции, тембра и естественной динамики.

## 2. Задачи анализа

| Задача | Классический DSP достаточен? | Нейросеть нужна? | Чем управляет |
|---|---|---|---|
| Детекция атак | Да (onset detection, спектральный поток) | Нет | Блокирует смену параметров во время атаки |
| Сибилянты / шумовые согласные | Обычно да (ВЧ-энергия, ZCR, спектральный наклон) | Возможно, для устойчивости | Выбор участков для оценки ВЧ-характера исходника |
| Гласные / форманты | Да (LPC, отслеживание формант) | Возможно | Выбор участков для оценки НЧ и дистанции |
| Уровень / динамика | Да | Нет | SPL для нелинейности |
| Оценка дистанции и угла источника | Ограниченно | **Вероятно да** | r_s, θ_s |
| Определение исходного микрофона | Нет | **Да** | Выбор модели источника и доверие |
| Спектральные особенности (тилт, баланс) | Да | Нет | Диагностика, доверие |

**Вывод (INFERRED):** нейросеть оправдана для двух задач — определения исходного микрофона и оценки позиции. Остальное надёжнее и дешевле делать классическими DSP-признаками. Это проверяется на эталонных парах.

## 3. Разрешено и запрещено

**Разрешено управлять:** r_s, θ_s, тип исходника и доверие, SPL-оценка, параметры сглаживания, сила коррекции (по доверию).

**Запрещено:** прямое изменение звука по типу фонемы (например, «приглушить сибилянты, потому что целевой микрофон так звучит»), если это не следует из модели микрофона. Такие функции допустимы только как явно включаемая пользователем опция вне модели, и в журнале решений это фиксируется отдельно.

## 4. Режимы работы
| Режим | Описание | Задержка | Качество оценок |
|---|---|---|---|
| Real-time | Причинный анализ, кадры 10–20 мс (INFERRED), отдельный поток | Без lookahead | Ниже: нет будущего контекста |
| Pre-analysis | Анализ всего дубля до обработки (ARA2 в поддерживающих DAW, либо явный проход) | Не влияет на воспроизведение | Выше: полный контекст, сглаживание вперёд и назад |

## 5. Локальность и нагрузка
- **Только локальный инференс, без облака** (приватность, офлайн-работа, детерминизм).
- Предобученная модель поставляется с плагином. Обучение в плагине не выполняется.
- Кандидаты для инференса: ONNX Runtime, RTNeural, собственная реализация небольших сетей. Это **кандидаты, а не решения**: выбор после бенчмарков.
- Нагрузка: небольшая сеть на control rate ожидаемо занимает малую долю ядра (INFERRED). Цифры — UNKNOWN до прототипа.
- Анализ выполняется вне аудиопотока. Если анализ не успевает, используются последние валидные параметры, а аудио не прерывается.

## 6. Adaptive Control Engine
- Принимает оценки с доверием и превращает их в параметры DSP.
- Сглаживание (гистерезис, ограничение скорости), блокировка изменений на атаках.
- Масштабирование силы коррекции по доверию.
- Детерминизм: один и тот же вход и настройки дают один и тот же результат, в том числе при офлайн-рендере.

## 7. Данные для обучения и проверки
- Эталонные пары и многомикрофонные записи с известными позициями (12).
- Синтетические данные: «чистый» вокал × измеренные модели микрофонов × позиции. Только для обучения оценщиков, не для звука.
- Проверка обобщения на голосах и микрофонах, не входивших в обучение.

## 8. Вопросы исследования (из брифа)
1. Нужна ли нейросеть в плагине или достаточно предобученной модели? → Предобученная модель внутри плагина, только инференс (рекомендация).
2. Локально без облака? → Да (требование).
3. Предварительный анализ? → Да, режим Pre-analysis.
4. Реальное время? → Да, причинный режим с более низкой точностью оценок.
5. Нагрузка и задержка? → Бенчмарк на прототипе. Сейчас UNKNOWN.
6. Разделение AI и DSP? → Разные потоки, обмен только параметрами (01).
