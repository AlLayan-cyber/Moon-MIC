# План валидации MOON MIC Physical Capsule Engine

## 1. Сначала проверить математику
- тест одного затухающего осциллятора;
- сравнение численного решения с аналитическим решением;
- проверка полюсов и устойчивости;
- проверка поведения при изменении sample rate;
- тесты на NaN/Inf и экстремальные параметры.

## 2. Проверить линейную модель
- импульсный отклик;
- логарифмический sweep;
- частотная характеристика;
- фаза и групповая задержка;
- переходные процессы;
- сравнение с reference implementation в Python.

## 3. Проверить нелинейности
- уровни входа с разницей 6 dB;
- harmonic distortion;
- intermodulation;
- aliasing;
- сравнение oversampling 2x/4x/8x;
- отсутствие нестабильности при экстремальных значениях.

## 4. Идентификация параметров
Не пытаться извлечь все физические параметры из одной АЧХ. Использовать несколько типов данных:
- частотная характеристика;
- импульсный отклик;
- полярные измерения;
- измерения при нескольких уровнях;
- известная геометрия;
- электрические измерения, если доступны.

Разделять:
- параметры, непосредственно измеренные;
- параметры, оценённые fitting;
- параметры, которые неидентифицируемы по имеющимся данным.

## 5. Сравнение с реальным C-800G
Для честной проверки нужны:
- известный экземпляр;
- калиброванный источник;
- известная дистанция и угол;
- контролируемая акустическая среда;
- известный предусилитель/измерительный тракт;
- несколько уровней звукового давления.

Если такого набора нет, результат называть сравнением с доступными опубликованными данными, а не полной валидацией оригинала.

## 6. Критерии готовности прототипа
- стабильность на типичных частотах дискретизации;
- CPU budget измерен;
- latency известна;
- воспроизводимость offline и realtime;
- параметры имеют документированную физическую интерпретацию;
- ошибки относительно reference data измерены и опубликованы внутри проекта;
- ограничения явно перечислены.
