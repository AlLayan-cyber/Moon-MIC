# MOON MIC — техническая архитектура Virtual Physical Capsule Engine

## 1. Концепция

Цель — цифровая модель преобразователя, а не только фильтр частотной характеристики.

Физическая цепочка:

`acoustic pressure → air load → membrane displacement → variable capacitance → electrical signal → microphone electronics`

Модель должна быть редуцированной и пригодной для realtime DSP. Полноценная CFD/FEM-симуляция на каждом аудиосэмпле не является стартовым решением.

## 2. Модульная структура

### 2.1 Acoustic Input
Входной сигнал представляет оценку звукового давления. В обычном плагине это условная величина, потому что на вход приходит сигнал другого микрофона. Для физической интерпретации требуется калибровка источника/микрофона и учёт входного тракта.

### 2.2 Acoustic Load Model
Моделирует нагрузку воздуха на обе стороны мембраны:
- акустическую массу;
- вязкое сопротивление;
- акустическую податливость полостей;
- импеданс отверстий backplate;
- взаимосвязь передней и задней полостей.

Начать с lumped acoustic network или state-space модели. При наличии геометрии исследовать reduced-order approximation распределённой акустики.

### 2.3 Membrane Modal Model
Представить движение мембраны суммой модальных форм:

`x(r, θ, t) = Σ φ_n(r, θ) q_n(t)`

Для каждой моды:

`m_n q_n''(t) + c_n q_n'(t) + k_n q_n(t) = F_n(t)`

где:
- `m_n` — эффективная модальная масса;
- `c_n` — модальное демпфирование;
- `k_n` — модальная жёсткость;
- `q_n` — модальная координата;
- `φ_n` — пространственная форма моды;
- `F_n` — проекция акустического давления на форму моды.

Линейная модель — первый этап. Нелинейность натяжения и геометрии добавлять только при доказанной необходимости и наличии данных.

### 2.4 Backplate / Gap Model
Учитывает:
- исходный зазор;
- пространственную неоднородность зазора;
- отверстия и каналы;
- локальную акустическую нагрузку;
- ограничение перемещения и риск pull-in как физическое явление.

Неизвестную геометрию нельзя придумывать. Допускается параметрическая модель с неопределённостью.

### 2.5 Capacitive Transducer
Для идеализированного локального элемента:

`dC = ε dA / (d(r,θ) - x(r,θ,t))`

Общая ёмкость:

`C(t) = ∫_A ε / (d(r,θ) - x(r,θ,t)) dA`

Это приближение требует корректной геометрии, граничных условий и учёта краевых эффектов. Не считать его полной электромагнитной моделью.

### 2.6 Electrostatic Coupling
Исследовать:
- напряжение поляризации;
- электростатическую силу;
- изменение силы при изменении зазора;
- влияние электрической нагрузки;
- возможную обратную связь между механикой и электрическим полем.

Нужна проверка устойчивости и отсутствия численного разгона.

### 2.7 Capsule Electrical Model
Моделирует электрическую часть преобразователя:
- ёмкость капсюля;
- утечки/сопротивления;
- поляризационную цепь;
- входное сопротивление первого каскада;
- паразитные ёмкости и кабельную нагрузку, если подтверждены.

### 2.8 Microphone Electronics Model
Отдельный модуль. Для C-800G исследовать ламповый тракт и выходной каскад по сервисной документации. Не смешивать его с капсюлем.

### 2.9 Calibration / Residual Correction
Небольшая измеренная коррекция допустима для остаточной ошибки. Она должна быть отдельным, видимым слоем, а не подменять физическую модель.

## 3. Рекомендуемые уровни реализации

### Level 1 — linear modal capsule
- несколько доминирующих мод;
- линейная акустическая нагрузка;
- state-space или biquad/state-variable реализация;
- проверка импульсной характеристики и АЧХ.

### Level 2 — coupled acoustic/electromechanical model
- две акустические стороны;
- задний электрод и отверстия как акустическая сеть;
- переменная ёмкость;
- электростатическая обратная связь;
- режимы направленности.

### Level 3 — nonlinear reduced-order model
- нелинейная зависимость ёмкости от локального зазора;
- нелинейная электростатическая сила;
- возможные амплитудно-зависимые эффекты;
- oversampling и контроль aliasing;
- оптимизация CPU.

## 4. Реализация

Рекомендуемый workflow:
1. Python/Numpy/SciPy — исследовательская модель.
2. Jupyter или скрипты — построение графиков и fitting.
3. Unit tests — проверка устойчивости и граничных случаев.
4. C++ — realtime ядро.
5. JUCE/VST3 — только после валидации модели.

Не выполнять тяжёлые операции выделения памяти, логарифмы, интегралы по сетке или нелинейный solver без ограниченного worst-case времени в audio callback.

## 5. SIGNATURE и TRANSFORM

### SIGNATURE
Использует параметры физической модели, идентифицированные/калиброванные под конкретную модель микрофона, затем отдельный слой электроники и residual correction.

### TRANSFORM
Использует Capsule Engine как целевую модель характера. Но преобразование записи с другого микрофона в целевой микрофон — inverse/forward problem с неполной информацией. Нельзя гарантировать восстановление информации, которой нет в исходном сигнале. Нужны контролируемые обучающие пары или измерительные данные.

## 6. Расширение на другие микрофоны

Архитектура должна отделять общий solver от параметров конкретного капсюля. Для каждого микрофона хранить capsule profile:
- geometry;
- membrane;
- acoustic network;
- electrical coupling;
- polar pattern configuration;
- provenance and confidence metadata.

Не предполагать, что все микрофоны используют одну геометрию или одну модель капсюля.
